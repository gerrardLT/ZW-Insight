## 一、调研背景与核心结论

### 1.1 背景判断（属实）

当前系统资金管理模块的业务深度与行业要求存在**显著差距**：

| 差距类别 | 本系统现状（代码取证） | 行业应达到标准 | 差距程度 |
|---------|----------------------|----------------|----------|
| **资金分类体系** | 无收支分类科目，仅按合同类型（contract_category）粗分 | 多维度科目体系（至少 3 级），支持自定义扩展 | 🔴🔴 重大 |
| **资金计划深度** | `FundPlanItemVO` 仅按月聚合已审批付款申请，单维度应付预测 | 年度预算 + 月度计划 + 滚动预测 + 缺口分析三层联动 | 🔴🔴 重大 |
| **保证金管理** | 仅有质保金（BizRetentionMoney）单类 | 投标/履约/质量/工资四类全生命周期 + 保函替代 | 🔴🔴🔴 严重 |
| **农民工工资专户** | 无 | 国务院令第 724 号强制要求：专户管理、总包代发 | 🔴🔴🔴 严重 |
| **票据管理** | 无（开票/收票仅发票登记） | 应收/应付票据台账 + 背书/贴现 | 🟡 中度 |
| **融资借贷管理** | 无 | 借款台账 + 利息计算 + 还本付息计划 | 🟡 中度 |
| **老板视角报表** | 基础统计 | 垫资分析、两金压控、现金流预测、资金日报 | 🔴🔴 重大 |

### 1.2 核心结论（先给答案）

1. **资金分类必须建多维体系**，不能只有单一维度：推荐「按资金性质 / 按业务来源 / 按形态 / 按权属阶段」四维并行，其中**按资金性质**是老板看板的骨架
2. **资金流转闭环 = 产值/结算/收付三口径 + 四类保证金 + 工资专户**：当前系统只做了"收付"一角
3. **老板最关心的前三指标**：垫资规模、经营性现金流净额、回款率（三者分别回答"钱压出去多少""主业造血行不行""钱收回来没"）
4. **合规是硬约束**：农民工工资专户与工资保证金不是"锦上添花"，是条例强制，违规面临停工 + 5-10 万元罚款 + 资质降级

**关键证据**：
- `biz_payment_apply` 表（`00_schema.sql`）仅有：project_id / contract_id / **contract_category** / supplier_id / payment_amount / payment_date / 快照字段 / status —— **没有任何"资金分类科目"概念**
- `FinanceStatisticsService.getFundPlan()`（第 84 行起）：资金计划 = 按付款日期月份聚合**已审批付款申请**，输出 month + plannedAmount + applyCount 三个字段 —— 仅是"应付侧单维预测"，无收款预测、无净缺口、无计划 vs 实际
- 全库 Grep「融资|票据|承兑|借款」在 SQL 层 **0 命中**：票据与融资管理完全空白

### 2.2 现有资金流转链路（已实现部分）

```
【收入侧】产值上报(OUTPUT) → 开票申请(校验 ≤ 累计产值-已开票) → 回款登记(回写项目总收入+合同累计收款)
【支出侧】四类支出合同结算(只回写各自 cumulative_settlement) → 付款申请(校验 ≤ 累计结算-已付)
          → PaymentApplyService.onApproved() ★全系统唯一回写项目 total_expense 的入口（付款口径纪律）
【项目层】biz_project.total_income / total_expense / total_other_payment / cumulative_output
【控制】  @BudgetCheck AOP 预算硬控制（超预算拦截）
【封账】  FinanceLockController 月度/年度封账
```

### 2.3 现状结论

**已有骨架是对的**（付款口径统一、预算硬控制、对称回滚），缺的是**分类维度、计划深度、合规专项、老板报表**四块——这正是本次优化的靶心。

## 四、第三路调研：政策法规与行业标准（数字精确可引用）

### 4.1 《保障农民工工资支付条例》（国务院令第 724 号，2020-05-01 施行）

| 条款 | 要求 | 系统功能点 |
|------|------|-----------|
| 第 23 条 | 政府投资项目不得由施工单位垫资；建设单位须有资金安排 | 垫资预警 |
| 第 24 条 | **人工费用拨付周期不得超过 1 个月**；建设单位提供支付担保 | 人工费月度拨付计划 |
| 第 26 条 | **开设农民工工资专用账户** | 专户开户与标识 |
| 第 29 条 | 建设单位将人工费**及时足额拨付至专户** | 拨款到账对账监控 |
| 第 31 条 | **总包代发**：通过专户直接支付到农民工个人银行账户 | 代发台账 |
| 第 32 条 | **存储工资保证金**，可用金融机构保函替代 | 保证金存储管理 |
| 第 33 条 | 专户资金和工资保证金**不得因其他原因被查封、冻结、划拨** | 专户隔离保护标识 |
| 第 55 条 | 违规：责令停工 + **5-10 万元罚款**；情节严重限制承接新工程、资质降级 | 合规检查追溯 |

### 4.2 四类保证金政策（唯一允许保留的四类，国办发〔2016〕49 号）

| 保证金 | 比例上限 | 退还规则 | 法规依据 |
|--------|---------|---------|---------|
| **投标保证金** | ≤招标项目估算价 **2%** | 中标后签合同 5 日内退还；未中标收到通知后 5 日内 | 《招标投标法实施条例》第 26、57 条 |
| **履约保证金** | ≤中标合同金额 **10%** | 竣工验收合格后退还 | 同上第 58 条 |
| **质量保证金** | ≤工程价款结算总额 **3%** | 缺陷责任期一般 1 年最长 2 年；收到返还申请后 **14 天内核实** | 《建设工程质量保证金管理办法》（建质〔2017〕138 号） |
| **农民工工资保证金** | **1%-3%**（合同额比例） | 完工 + 公示 30 日 + 人社部门 5 个工作日审核 | 人社部发〔2021〕65 号 |

**工资保证金信用规则（人社部〔2021〕65 号）**：
- 合同额 **< 300 万元** 且无拖欠历史 → 可免存
- 连续 **2 年**未拖欠 → 新工程存储比例**降 ≥50%**
- 连续 **3 年**未拖欠 + 落实实名制专户 → **可免于存储**
- 发生拖欠 → 比例**提高 ≥50%**；严重失信名单 → **提高 ≥100%**
- 动用后 **10 个工作日内**补足
- 存储形式：现金 / 银行保函 / 工程担保公司保函 / 工程保证保险

### 4.3 资金管理理论框架

**「产值 / 结算 / 收付」三口径**（工程行业资金理解的地基）：

```
产值（履约进度确认收入，CAS 14）     ← 合同资产增加，"做了还不算钱"
  ↓ 等待业主确权（典型 3-12 个月）
结算（取得无条件收款权）            ← 合同资产转应收账款，存在审减风险
  ↓ 等待业主付款（典型 6-24 个月）
收付（实际现金流入）                ← 银行存款增加，可能被票据/甲供材抵扣
```

**三口径差额就是老板最痛的垫资**：垫资 = 累计产值（或结算）- 累计收款。

**施工企业垫资的制度性根源**：进度款支付比例 ≤80%、次月付上月、质保金 3% 长期占用、政府项目财政延期。

**司库管理**（国资发财评规〔2022〕1 号，央企标准可借鉴民企）：多账户归集、资金集中管控、头寸预测、收支两条线。

**两金压控**（国资委持续考核）：(应收账款 + 存货) / 资产总额，占比过高说明资产质量差。

## 五、资金分类体系设计（核心结论）

### 5.1 四维分类框架

从政策、竞品、会计准则三个独立来源交叉推导，资金分类应**四维并行**（不同维度回答不同问题）：

#### 维度 1：按资金性质（老板看板的骨架——"这是什么钱"）

```
├─ 营业收入类
│  ├─ 工程进度款
│  ├─ 竣工结算款
│  ├─ 变更签证款
│  └─ 其他营业收入
├─ 专项资金类（专款专用，不得挪用）
│  ├─ 农民工工资专户资金
│  ├─ 税款专户
│  └─ 社保专户
├─ 保证金类（占用状态跟踪）
│  ├─ 投标保证金（≤2%）
│  ├─ 履约保证金（≤10%）
│  ├─ 质量保证金（≤3%）
│  └─ 农民工工资保证金（1%-3%）
├─ 内部往来类
│  ├─ 备用金
│  ├─ 内部资金调拨
│  └─ 押金/暂收暂付
└─ 融资类
   ├─ 银行借款
   └─ 融资利息支出
```

#### 维度 2：按业务来源（对应支出合同——"钱为哪个合同花的"）

材料款 / 分包工程款 / 劳务款（含工资）/ 机械租赁费 / 人工费 / 间接费用（办公/差旅/招待）/ 税费 / 其他

> 说明：该维度与现有 contract_category + 预算二级科目（CostSubcategory）天然衔接，是**阻力最小的落地面**。

#### 维度 3：按形态（"钱以什么形态存在"）

现金及银行存款 / 银行承兑汇票 / 商业承兑汇票 / 保函（替代现金的保证金形态）/ 保证保险

#### 维度 4：按权属阶段（"这笔钱处在闭环哪一段"）

合同资产（已完工未结算）/ 应收账款（已结算未收款）/ 预收账款（已收款未履约）/ 应付账款 / 预付账款

### 5.2 分类落地为可执行的记录处理规则

| 单据 | 新增分类字段 | 联动效果 |
|------|------------|---------|
| 付款申请 | payment_category（支出科目，维度 1+2 编码） | 按科目汇总支出结构 |
| 回款登记 | receive_category（收入科目） | 按科目汇总收入结构 |
| 保证金台账 | bond_type + bond_form | 保证金占用总额/保函替代率 |
| 工资专户 | 专户隔离标识 | 专款余额独立监控 |
| 资金计划 | 年度/月度/滚动三层 | 计划 vs 实际执行率 |

**历史数据处理**：存量付款申请无分类字段 → 管理员"一键补填" + 审计日志（禁止静默填默认值，遵守真实数据原则）。

## 六、资金流转真实闭环（全景图）

```
┌─────────────────────────── 收入侧（钱进来）───────────────────────────┐
│                                                                        │
│  施工合同 ──→ 产值上报 ──→ 【口径1:产值】累计产值                       │
│                  │                                                    │
│                  ↓ 业主确权                                            │
│              变更签证/结算 ──→ 【口径2:结算】应收账款                    │
│                  │                                                    │
│                  ↓ 开票申请（校验≤累计产值-已开票）                     │
│              开票 ──→ 税项联动（销项）                                  │
│                  │                                                    │
│                  ↓ 回款登记（回写项目总收入+合同累计收款）                │
│              【口径3:收付】银行账户/专户到账                             │
│                  │                                                    │
│                  ├──→ 普通账户（基本户/一般户）                         │
│                  └──→ 专项资金（工资专户★条例强制，隔离保护）             │
│                                                                        │
├─────────────────── 资金占用（钱压在哪）────────────────────────────────┤
│                                                                        │
│  四类保证金：投标(≤2%) / 履约(≤10%) / 质量(≤3%) / 工资(1%-3%)          │
│  ├── 现金缴存 ──→ 台账跟踪 ──→ 到期预警 ──→ 退还/补足                   │
│  └── 保函/保险替代 ──→ 保函文件管理 ──→ 替代率统计                       │

│  垫资 = 累计产值（或结算） - 累计收款  ← 老板第一痛点指标                 │

├─────────────────── 支出侧（钱出去）───────────────────────────────────┤

│       ├── 分包款   ← 分包合同结算                                       │
│       ├── 劳务款   ← 劳务结算/工资单（工资走专户代发★条例强制）           │
│       ├── 机械款   ← 机械结算（台班/加油/维修）                          │
│       └── 间接费用 ← 报销/其他付款                                      │
│  唯一回写点：PaymentApplyService.onApproved → 项目 total_expense        │
│                                                                        │
├─────────────────── 老板看板（钱看得见）────────────────────────────────┤
│                                                                        │
│  垫资规模与垫资率 / 经营性现金流净额 / 回款率                           │
│  应收账款周转 / 两金占比 / 资金缺口滚动预测 / 保证金占用与到期预警        │
│  工资专户到位率（合规红线）/ 超计划付款预警                              │
└────────────────────────────────────────────────────────────────────────┘
```

## 七、老板最关心的业务（指标体系，按优先级）

**设计立场**：系统是做给老板看的。老板不是会计，不关心借贷科目；老板关心的是**钱压了多少、还能不能转、什么时候回来、哪里在漏**。

| 优先级 | 指标 | 公式/定义 | 回答老板什么问题 |
|--------|------|----------|----------------|
| 🥇 P0 | **垫资规模与垫资率** | 垫资 = 累计产值 - 累计收款；垫资率 = 垫资/累计产值 | 我的自有资金压在项目里多少？ |
| 🥈 P0 | **经营性现金流净额** | 经营现金流入 - 流出（收付口径，非权责发生） | 主业是造血还是失血？ |
| 🥉 P0 | **回款率** | 实际回款 / 应回款（按结算口径） | 钱收回来没有？谁欠最多？ |
| P1 | 应收账款余额及周转天数 | 应收账款 / 月均回款 | 资金被业主占用多久？ |
| P1 | 资金缺口滚动预测 | 未来 N 月(应付+还贷) - (可用资金+预计收款) | 会不会断粮？要提前融资吗？ |
| P1 | 保证金占用与到期预警 | 四类保证金占用总额 + 即将到期清单 | 压在保证金里的钱多少？该退的退了吗？ |
| P2 | 两金占比 | (应收账款+存货)/总资产 | 资产质量考核线（国企红线） |
| P2 | 工资专户到位率 | 专户实收人工费 / 合同约定人工费 | 会不会因欠薪被停工罚款？ |
| P2 | 超计划付款预警 | 无计划付款 / 超预算付款笔数金额 | 哪些项目在失控？ |

**看板交互要求**（借鉴广联达决策看板）：汇总 → 项目 → 单据**三级穿透**；开累/年累切换；移动端可看。
