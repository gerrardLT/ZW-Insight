## 一、权限模型（三级，`E`）

### 1.1 模型结构

| 层级 | 载体 | 证据 |
|---|---|---|
| **菜单级** | 权限接口 `menu` 树（**309 节点**） | `GET /sys/permission/getUserPermissionByToken` |
| **按钮级** | `codeList` / `auth[]`（`type=1`） | 同上，38 条 |
| **字段级** | `type=2` 条目，语义"禁用" | 同上（如 `user:form:phone` → 「手机号禁用」） |
| **数据级** | 角色 `dataScope` / `deptDataScope` / `neDataScope` | `/sys/role/list` 字段 |

> **发现（`E`）**：本产品权限模型比 ZW-Insight 多一层——**字段级权限**（`type=2`，`describe` 直接写"禁用"）。例：`user:form:phone`（手机号禁用）、`demo.dbarray`（禁用）。这意味着**同一表单对不同角色可隐藏/禁用个别字段**。ZW-Insight 目前为"菜单 + 按钮 + 数据范围"三层，**无字段级权限**。→ 见 06 卷借鉴项。

> **观察 1（`E`）**：**6 条独立的"去(取消)支付"权限**——付款登记 / 薪资发放 / 其他支出 / 费用报销 / 备用金 / 借款单，**每条资金通道各自授权**。这说明"标记已支付"是一个**受权限管控的敏感动作**，且**权限粒度到"资金通道"**。
> **观察 2（`E`）**：`describe` 里出现 `demo.dbarray`（演示残留）→ 说明**权限表未做上线清理**，属工程完成度信号。
> **观察 3（`E`）**：`doc:folder:permission` → **文档文件夹支持独立权限**（文档级 ACL）。

## 六、成熟度 rubric 评分（仅在证据充分时）

**评分刻度**：`M0` 明确不支持 · `M1` 仅查询/展示 · `M2` 可完成单点业务操作 · `M3` 有流程、状态与权限控制 · `M4` 形成跨模块闭环并有审计/消息 · `M5` 有自动化、预测、异常治理或优化能力 · `MU` 证据不足禁止评分。
**约束**：`vendor_claim` 不得单独评到 M3 以上；`not_found` 不得评 M0。

| 能力域 | 成熟度 | 理由 |
|---|---|---|
| 采购寻源（招标/询价/竞价） | **M5** | 多轮竞价 + 密封解密 + 专家/价格双决标 + 保证金闸门 + 评分项配置 → 有"优化/博弈"能力 |
| 合同全生命周期 | **M4** | 9 段累计 + 4 状态维度 + 签证/执行/结算 + 修订版本 + 文档联动 |
| 采购物资链 | **M4** | 申请→寻源→订单→入库→结算→付款 全链 + 自动入/出库开关 |
| 资金与发票 | **M4** | 三段占用 + OCR 发票 + 发票夹 + 6 通道支付权限 |
| 成本归集 | **M3** | 有归集与核实留痕，但无恒等守卫与自动对账（未达 M4"跨模块闭环并有审计"的强度） |
| 供应商管理 | **M4** | 平台化入驻 + 7 档分级 + 信用核验 + 黑名单留痕 |
| 施工/现场 | **M3** | 进度/日志/质安闭环/点工/花名册齐备，但未见 IoT、定位等 M5 能力 |
| 加工厂（生产） | **M4** | 完整生产制造链路 |
| 预警 | **M3** | 规则可配置 + 分类，但未见自动扫描任务证据 |
| 权限 | **M4** | 菜单/按钮/**字段**/数据范围 四层 |
