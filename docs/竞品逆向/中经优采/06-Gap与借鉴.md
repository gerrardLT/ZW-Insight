# 竞品逆向 · 中经优采（天工工程云）· 06 差距与借鉴

> 建立日期：2026-10-10 ｜ 对照基准：ZW-Insight 真实资产（22 模块 / 150 张 `biz_` 表 / 891 端点 / 33 BPMN / 20 定时任务，见 §五 基准说明）

## 一、结论摘要

**中经优采在"采购寻源"这一域对 ZW-Insight 形成明显领先，在"经营分析与资金治理"上明显落后。** 两者不是替代关系，而是**能力互补**：

- **必须闭环（P0）**：多轮竞价引擎、密封报价解密、二轮询价、报价要求开关组、双决标方式 + 评分项配置、保证金/报名费闸门、付款订单级三段占用、付款比例 100% 硬校验、成本核实留痕、预警规则可配置。
- **细节增强（P1）**：招标节点时间轴、合同 9 段累计一行呈现、发票 OCR/发票夹、字段级权限、供应商 7 档准入、信用中国核验、单据-文档目录绑定、列表字段设置、自动入/出库开关、PDF 导出模板；**以及经营分析层 11 项（P1-16~26，见 07 卷）**：指标三元组下发、无关联收付单列、报销三向冲抵、统一资金支付中心、公户/私户分类、工程量-材料-损耗联动、项目 360 双口径并列、备用金实时余额校验、资金账户级授权、还款金额拆分、报销单跨项目明细。
- **锦上添花（P2）**：深色模式、多页签工作区、代报价、AI 助手、公开标讯/中标公示。
- **不可借鉴（反面清单）**：编号规则不统一、闭合判据以文件上传为准、招标日期无先后校验、预警默认未启用且无自动扫描、附件阈值不一致、行业特化模块（加工厂/铜铝价格/新能源）直接照搬。

## 三、必须闭环（P0，建议进下一迭代）

### P0-1 ★★★ 多轮竞价引擎（本产品最明确领先项）

| 项 | 竞品实现（`E`） | ZW-Insight 现状 |
|---|---|---|
| 模式 | **竞价 / 拍卖** 两向 | 无 |
| 报价方式 | **按物料竞价 / 按总价竞价** | 无 |
| 价格规则 | **起拍价** + **价格梯度**（明细级） + **最小报价单位数** | 无 |
| 轮次 | 多轮（`竞价次数` 计数、`最后报价`） | 单轮 |
| 大厅 | `竞价大厅(按总价报价模式)` / `竞价大厅(按物料报价模式)` | 无 |
| 排名 | `竞价排名` / `公开竞价排名` / `公开竞价价格` | 有评标排名（`biz_bid_result`）但非实时竞价 |
| 约束 | `竞价金额需大于0`、`竞价规则，请务必阅读！`、`竞价协议`勾选 | — |

**建议**：在 `zw-purchase` 增加 `biz_bidding` / `biz_bidding_item`（起拍价、价格梯度、最小单位数）/ `biz_bidding_quote`（多轮报价流水）；前端新增"竞价大厅"实时页（WebSocket 推送）。**这是竞品最值得照抄的机制**。

### P0-2 ★★★ 密封报价 + 开标解密

| 项 | 竞品（`E`） | ZW 现状 |
|---|---|---|
| 报价保密 | **开标密码** + **报价解密时间** | 无（报价直接可见） |
| 证据 | 文案 `请填写开标密码!`、`请输入开标密码`、`请填写报价解密时间!`、`报价解密时间` | — |

**建议**：`biz_quotation` 增加密文存储（报价在截止前加密），开标时凭密码解密。**这是防串标的核心内控**，工程行业审计关注点。

### P0-3 ★★ 二轮询价

竞品（`E`）：`开启二轮询价` / `已开启二轮询价` / `一轮报价开始/结束` / `二轮报价开始/结束` / `供应商报价(一轮)/(二轮)` / `最后报价`。
**建议**：`biz_inquiry` 增加 `round`（轮次）+ 二轮起止时间；报价表按轮次分区。

### P0-4 ★★ 报价要求开关组（6 项）

竞品原文（`E`）：`含税报价` / `报价需要包含运费` / `允许对询价单部分物料报价` / `落地价` / `要求供应商上传投标文件` / `报价时需录入品牌`。
**建议**：`biz_inquiry` 增加 6 个布尔配置字段 + 供应商报价页据此动态显隐/校验。**成本极低、体验收益高**。

### P0-5 ★★ 双决标方式 + 评分项可配置

竞品（`E`）：`决标方式` 必填，取值 `专家决标` / `价格决标`；配套独立菜单 `技术评分项管理` + `商务评分项管理`。
**建议**：ZW 已有 `biz_bid_result` 排名，建议增加 `awardMethod`（PRICE/EXPERT）+ `biz_score_item`（技术/商务评分项字典表），专家决标走评分表。**这是"询价"与"招标"的分水岭**。

### P0-6 ★★ 保证金/报名费闸门 + 凭证审核

竞品（`E`）：询价/竞价表单**必填** `报名费` + `缴纳保证金`；文案 `请上传保证金凭证!` / `请上传报名费凭证!` / `请填写保证金!`；状态 `未缴纳` / `已缴纳待审核`；独立菜单"保证金管理"。
**建议**：ZW 的 `biz_security_bond` 已有基础，建议补齐"报名费"独立科目 + 凭证上传 + 待审核状态 + 未缴费拦截报价。

### P0-7 ★★★ 付款申请：订单级三段占用（防超付）

竞品明细列（`E`）：`采购订单 | 订单金额 | 已申请金额 | 申请中金额 | 可申请金额 | 本次申请金额`
→ **"申请中"单列 = 审批中的申请也占用额度**。

ZW-Insight 现状：`pay_status`（现金口径）与审批口径分离，但**未见"申请中占用"的额度控制**。
**建议**：付款申请明细增加 `applyingAmount`（在途）并做 `可申请 = 订单金额 − 已申请 − 申请中` 的**硬拦截**。这是**防重复付款/超付**的关键机制，工程审计高频问题。

> **补充（07 卷字段级实证）**：同一"四段占用"模型在本产品被**复用到两条链**——付款侧（`已申请 / 申请中 / 可申请`）与**开票侧（`已开票 / 开票中 / 可开票`，见进项发票表单）**；且**付款登记表单含只读字段 `付款申请`**，说明付款申请→付款登记是派生关系。建议 ZW-Insight 把"总量 − 已占用 − 在途 = 可用"抽象为**通用额度占用组件**，一次覆盖付款与开票。

### P0-8 ★★ 付款比例合计 100% 硬校验

竞品（`E`）：`付款比例总和需为100%` / `收款比例总和需为100%`，且合同"付款计划明细"的 `付款比例(%)` 为**必填列**。
**建议**：ZW 合同/资金计划增加比例合计校验（前后端双校验）。

### P0-9 ★★ 成本归集"核实"环节 + 留痕

竞品（`E`）：成本中心有 `核实` / `取消核实` 操作 + `verified` / `verifierId` / `verifierName` / `verifyTime` 留痕。
**建议**：ZW 的 CBS 归集是**自动对账**（`CostRollUpTask`），但缺"人工确认"环节。建议在成本账户增加 `verified` 字段 + 核实/取消核实操作，**形成"机器对账 + 人工核实"双保险**。

### P0-10 ★★ 预警规则可配置（当前 ZW 为硬编码）

竞品（`E`）：`warningRule`（规则）+ `warningRuleParam`（参数）+ `warningScope`（范围）+ `receiver`（接收人，支持部门）+ `noticeTemplate`（模板）+ `warningStatus`（启停）；5 分类（付款/成本/合同/劳务/进度）。

ZW-Insight 现状：`zw-dashboard/risk/rule/*.java` **7 条风险规则为代码硬编码**（`ProfitLossRiskRule`/`BudgetOverRiskRule`/`FundGapRiskRule`/…）。
**建议**：抽象出 `biz_risk_rule` 表（规则类型 + 参数 JSON + 启用 + 接收人 + 模板），把硬编码规则迁移为**可配置项**，同时保留代码规则作为兜底。**这直接提升交付灵活度**（客户可自助加规则，无需改代码发版）。

## 七、三阶段演进建议

### 阶段一（1 个迭代，低风险高收益）

1. **P0-4 报价要求开关组**（6 布尔字段 + 动态显隐）
2. **P0-8 付款比例合计 100% 硬校验**
3. **P1-2 / P1-3 合同 9 段与订单 6 段累计一行呈现**（纯展示，无模型改动）
4. **P1-9 黑名单留痕三字段**、**P1-11 列表字段设置通用化**
5. **P2-7 工作台逾期计数卡**

> 目标：**零模型风险**下显著提升"台账一眼到底"的体验。

### 阶段二（2–3 个迭代，核心能力补齐）

6. **P0-7 付款申请订单级三段占用（防超付）** ← 资金内控，优先级最高
7. **P0-10 预警规则可配置化**（抽象 `biz_risk_rule`，硬编码规则迁移）
8. **P0-9 成本归集"核实"环节 + 留痕**
9. **P0-5 双决标方式 + 技术/商务评分项配置**
10. **P0-6 保证金/报名费闸门 + 凭证审核**
11. **P1-1 招标节点时间轴**（若确定要做"采购方招标"）
12. **P1-4 发票 OCR + 发票夹**
13. **P1-6 供应商准入 7 档分级**

### 阶段三（3+ 迭代，机制级领先）

14. **P0-2 密封报价 + 开标解密**
15. **P0-3 二轮询价**
16. **P0-1 多轮竞价引擎（含竞价大厅实时推送）** ← 工作量最大，但**最能与竞品拉开差距**
17. **P1-5 字段级权限**
18. **P1-10 单据-文档目录绑定**
19. **P1-14 供应商入驻向导 + 邀请码**

## 十、一句话结论

**若只做一件事**：把「付款申请订单级三段占用（已申请 / 申请中 / 可申请）+ 可申请余额硬拦截」做出来——这是 ZW-Insight 与竞品在**资金内控**上的直接差距，且成本低、风险低、审计价值高。
**若只做一个方向**：做「多轮竞价 + 密封解密 + 二轮报价」——这是竞品唯一在本域**形成代差**的能力，也是 ZW-Insight 采购模块从"询比价"升级为"电子招采平台"的关键跳板。
