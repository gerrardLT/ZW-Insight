## 5. 目标状态机与业务不变量

**合同**：`DRAFT → SUBMITTED → EFFECTIVE`（驳回回 DRAFT）；`update` 白名单，状态与累计字段只能由流程/结算链路写。
**日志**：`DRAFT → CONFIRMED`；被未驳回的结算单引用后锁定；`settlementStatus` 仅由结算链路写。
**结算**：`草稿(0) → 审批中(1) → 已审批(2) / 已驳回(3)`（沿用）。
**进退场**：`REGISTERED/OUT_FIELD → IN_FIELD → OUT_FIELD`，只经 `/in`、`/out`，履历与台账状态同事务。

| 编号 | 不变量 |
|---|---|
| MI-1 | 合同总额与计价单价分离；结算只读单价，不再借用 `contractAmount` |
| MI-2 | 结算明细必须落到具体合同；无匹配合同**拒绝创建**，不得静默 0 元 |
| MI-3 | 合同累计结算 = Σ已审批结算明细（按合同），原子累加、删除/驳回对称回冲，且不超合同额 |
| MI-4 | 只有 CONFIRMED 日志可入结算；被占用期间不可改删 |
| MI-5 | IN_FIELD 台账必有一条未闭合进场记录；`currentProject` 由进退场维护；退场只被**本项目**未结算日志阻断 |
| MI-6 | 单一结算口径：合同累计、CBS、R7、驾驶舱、费用总览同源 |
| MI-7 | 每个审批节点必须有可办理的人：候选组映射真实角色且可签收，不得依赖超级管理员 |
