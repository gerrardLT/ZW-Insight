## 2. 数据考古发现

生产**未核实**：审批真实办理人、已审批入职与账号映射、账号tenant缺失率、离职仍有效会话、调动跨租户机构/岗位、行政库存/车辆状态均无本轮数字。种子与E2E不算真实员工实绩。隐私探针先聚合，不导出手机号、证件或密码哈希。

待执行只读SQL，先逐主机核对IP/容器/DB/企业，`:tenant`是绑定参数：

```sql
SELECT DATABASE(),@@hostname;
SELECT table_name,column_name FROM information_schema.columns
WHERE table_schema=DATABASE() AND table_name IN
('biz_entry_apply','biz_resign_apply','biz_transfer_apply','sys_user','sys_org','sys_post');
SELECT status,COUNT(*) n FROM biz_entry_apply
WHERE tenant_id=:tenant AND deleted=0 GROUP BY status;
SELECT COUNT(*) null_tenant FROM sys_user WHERE tenant_id IS NULL AND deleted=0;
SELECT r.status,u.status user_status,COUNT(*) n
FROM biz_resign_apply r LEFT JOIN sys_user u
ON u.id=r.user_id AND u.tenant_id=r.tenant_id AND u.deleted=0
WHERE r.tenant_id=:tenant AND r.deleted=0 GROUP BY r.status,u.status;
SELECT COUNT(*) missing_or_wrong_tenant_user
FROM biz_transfer_apply a LEFT JOIN sys_user u
ON u.id=a.user_id AND u.tenant_id=a.tenant_id AND u.deleted=0
WHERE a.tenant_id=:tenant AND a.deleted=0 AND u.id IS NULL;
```

先核列再查sys_org/sys_post目标归属及用户角色、机构授权残留；入职username匹配仅取脱敏计数，不能自动映射历史员工；缺sys表deleted/字段即修SQL，禁止错误当零。会话有效性须另行授权真实登录及只读会话元信息，SQL status=0不等于token已撤销。双机分别统计，9999/种子/测试标记单列。

## 5. 目标状态机与业务不变量

- 六类申请保留DRAFT→SUBMITTED→APPROVED / DRAFT，撤回只在无副作用阶段；审批通过与生效日期分开是否需要APPLIED状态由用户定，不默认造定时任务。
- HR-1：身份来自申请关联员工/账号，不是createdBy；创建账号ID同事务回写或可靠关联，历史缺映射留待人工。
- HR-2：申请、账号、机构、岗位及角色同租户；sys_*豁免TenantLine的路径显式校验，回调不得依赖请求线程碰巧存在租户上下文。
- HR-3：SUBMITTED条件更新及行数守卫；账号建/停/调与申请状态同事务，缺对象明确失败或可审计豁免，不日志伪装成功；并发回调仅生效一次。
- HR-4：入职不授SUPER_ADMIN或隐式全权限；使用一次性激活/强制改密策略，不共享默认密码。用户名/手机号全局唯一不擅改为租户唯一。
- HR-5：离职停用撤销可撤销会话与权限缓存；待办/项目责任移交有清单，不删除历史审批人和业务账；管理员/最后管理员保护明确。
- HR-6：调动只改变授权允许的部门岗位，原数据范围及时撤销，新角色须独立授权；禁止通过HR申请跨租户升权。
- HR-7：人事敏感附件与档案独立权限、脱敏、读取审计；财务和项目角色不能因archive:view读全体员工。
- HR-8：行政库存流水与余额一致、领用/归还可追溯；车辆申请时间冲突与归还状态、用印审批与实际用印分离。具体强制门禁待业务确认，不由入口证据认定已缺陷。
- HR-9：依赖沿hr→system/security方向复用受控账号命令；反向需要时用zw-common事件，Listener模块前缀，不吞业务异常；不把项目级联删除用于员工注销。

## 7. 生产语义与用户决策

Q1批准后立即生效还是按入离职日期生效；推荐先明确现有语义，再决定是否加APPLIED。Q2推荐取消共享初始密码，采用受控激活；存量账号是否强制改密须授权，不批量重置。Q3缺账号推荐失败；历史已清理员工可专门豁免并记录，不默认为成功。Q4确认离职撤会话/移交范围及调动角色保留规则，禁止AI自动授予角色。Q5确认员工档案可见角色、敏感字段与保留期。Q6行政B范围由用户决定，不能将API清单冒充全模块完成。

未来存量修复先双机独立只读核查并备份目标申请/账号/授权关联，脱敏审查、逐单映射；不得自动按姓名/手机号补账号或恢复离职用户。回滚业务状态不应自动重新激活账号/恢复高权限，需安全负责人确认。本轮不操作账号、Redis、角色或生产数据。
