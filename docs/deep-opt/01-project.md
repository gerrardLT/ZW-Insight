## 5. 目标状态机与业务不变量（领域建模）

### 5.1 目标状态机（v2）

```
DRAFT ──submit(可配审批)──▶ FILED ──tender.needTender=1──▶ TENDERING ──落标──▶ LOST(终态,归档复盘)
  ▲──撤回──                    │                                └──中标──▶ WON
  │                            └──needTender=0────────────────────────┘│
  │                                                                合同生效(准入校验)
  │                                                                    ▼
  │              PAUSED ◀──暂停(留痕)── CONSTRUCTION ──复工──▶ PAUSED 解除
  │                                        │
  │                                     竣工验收
  │                                        ▼
  │                                    COMPLETED ──结项审批(5条件)──▶ CLOSING ──▶ CLOSED
  └──────── 终止(审批,任意非终态) ──────▶ TERMINATED(终态)
```

### 5.2 业务不变量（新增/强化）

1. **I1 流转合法性**：状态只能沿上图边流转（白名单升级为转移边表）；终态 CLOSED/LOST/TERMINATED 不可出
2. **I2 开工准入**：DRAFT/FILED/WON → CONSTRUCTION 需"存在 EFFECTIVE 施工合同"（预算校验放 P2 预算模块做硬约束，此处先软提示）
3. **I3 周期完整性**：实际开工 ≤ 实际竣工；COMPLETED 必有实际竣工日；CONSTRUCTION 必有实际开工日（存量回填迁移）
4. **I4 变更留痕**：非 DRAFT 态的关键字段（业主/金额/周期）修改必须生成变更记录（who/when/old/new）
5. **I5 结项实口径**：款项结清条件改为「应收台账余额=已收（替换现 output−income 简化式）+ 应付清零 + 质保金全退 + 保证金全退 + 最终结算 APPROVED」
6. **I6 落标归档**：TENDERING→LOST 须记落标原因；LOST 项目不可再被任何业务单据引用

### 5.3 DB 变更清单（双轨迁移）

- `biz_project` 加列：planned_start_date/planned_end_date/actual_start_date/actual_end_date/terminate_reason/lost_reason；status 枚举加 LOST/PAUSED/TERMINATED（VARCHAR 存量兼容）
- 新表 `biz_project_change_log`（项目变更台账：field/old/new/operator/source）
- 新表 `biz_project_status_log`（流转日志：from/to/event/operator/remark——审计与看板"项目大事记"共用）
- 存量数据回填：actual_*_date 由合同生效/竣工验收时间推导（只读推导脚本先出报告再执行，单独确认）
