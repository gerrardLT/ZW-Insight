## 摘要（先给结论）

**一句话**：ZW-Insight 的**主干闭环**（报备→立项→投标→合同→预算→执行→成本→资金→关闭）是扎实且可跑通的——22 模块、146 张 `biz_` 表、≈892 端点、33 BPMN、20 定时任务；资金域与机械域尤其完整，成本一致性保障（CBS 流水恒等 + 自动归集对账）与滚动资金预测属**行业未见同类公开口径**的优势。

**但对照行业标准与头部产品，缺失的不是"点"而是"段"**，集中在四个方向：

| 方向 | 缺什么 | 性质 |
|---|---|---|
| **上游策划/设计** | 可研、施工组织设计、目标成本测算下达、**图纸/CDE/设计变更管理**、**索赔/反索赔** | 整段缺失（无表无接口） |
| **现场合规专项** | 质量四件套（实测实量/隐蔽验收/旁站/**见证取样**）、安全（**危大工程**/隐患排查双重预防）、技术交底、**劳务实名制+考勤** | 整段缺失（政策强制项） |
| **计划与成本"推演"内核** | **CPM 网络计划/关键路径/里程碑/资源计划**、**三算对比/EVM 挣值/完工预测(EAC)**、**限额领料/工程量-材料联动** | 停在"记录"，未到"推演" |
| **下游收尾/资金对称** | 竣工资料/结算审计/决算/档案移交/项目后评价、**应付台账**、保函台账、税务、在途额度占用 | 半成品或骨架 |

**根因**：系统是**"记录型台账 + 事后归集"**，不是**"推演型管控 + 事前预测"**；且**重商务轻现场/策划**、**单表 CRUD 多而跨环节闭环少**——这与 `feature-ledger` 里 **42% 页面停在 L1 单路径 CRUD**、通知/追溯/聚合分析三档缺口占多数的分布完全同构。

**最值得先做的三件（若只做三件）**：
1. **付款/开票"在途额度占用"**（防重复申请超额，资金内控硬缺口，成本低、审计价值高）——与中经优采逆向 P0-7 同源。
2. **劳务实名制 + 考勤 → 工资单** 上游打通（政策强制 + 现工资单"金额来自人工汇总工单、无考勤工时数据源"的断裂）。
3. **计划进度的 CPM 内核**（当前甘特是"树形时间条"，前端甚至挂了 dhtmlx 关键路径开关与 CPM 图例，但后端**根本没有依赖关系数据**——见 §5.5 幻影功能）。

## 一、调研口径与判定标准

### 1.1 覆盖度判定四档

| 判定 | 含义 |
|---|---|
| **完整** | 有表 + 有接口 + 有页面 + 有闭环回写 |
| **部分** | 有主体但缺关键环节 |
| **骨架** | 有字段/单表/只读聚合，但无业务闭环 |
| **缺失** | 无表无接口（整段没有） |

## 二、应有基准：行业标准给出的"完整链路"

### 2.1 GB/T 50326-2017《建设工程项目管理规范》的知识领域（19 章）

这是国内施工项目管理的母规范，是系统功能模块划分的权威依据。其**生命周期阶段**（术语 2.0.1）明确含"策划、勘察、**设计**、采购、施工、**试运行**、竣工验收和**考核评价**"——其中"设计""试运行""考核评价"是 SaaS 最常省略的三段。知识领域与模块映射：

| 章 | 知识领域 | ZW-Insight 对应 |
|---|---|---|
| 5 | 项目管理策划（规划大纲/实施规划） | **缺**（无策划书/施组设计） |
| 6 | 采购与投标管理 | 部分（投标方完整，招标方缺） |
| 7 | 合同管理（评审/订立/实施/控制/总结） | 部分（缺索赔） |
| 8 | **设计与技术管理** | **缺** |
| 9 | 进度管理（计划/控制/变更） | 部分（无 CPM） |
| 10 | 质量管理 | 部分（仅通用检查单） |
| 11 | 成本管理（计划/控制/核算/分析/考核） | 部分（缺三算/EVM/责任成本） |
| 12 | 安全生产管理 | 部分（缺危大/双重预防） |
| 13 | 绿色建造与环境管理 | **缺** |
| 14 | 资源管理（人力/劳务/材料设备/机具/资金） | 部分（缺实名制/限额领料） |
| 15 | 信息与知识管理（文件档案） | **骨架**（档案仅只读聚合） |
| 16 | 沟通管理 | 完整（消息/审批流） |
| 17 | 风险管理 | 完整（7+1 类规则 + 台账） |
| 18 | **收尾管理**（竣工/结算/决算/保修/总结） | 部分（缺决算/总结） |
| 19 | 管理绩效评价 | **缺**（无后评价） |

### 2.2 政策强制/高频合规项（可直接映射为系统功能）

| 合规项 | 依据 | 系统功能要求 | ZW 现状 |
|---|---|---|---|
| **农民工工资专户 + 总包代发** | 国务院令第 724 号第 26/31 条 | 专户台账 + 三方协议 + 拨付周期≤1月 + 代发指令与凭证 | 财务域有专户台账，**与劳务工资单不联通** |
| **实名制 + 电子考勤** | 建市〔2019〕18 号 | 实名花名册 + 考勤（门禁/人脸）+ 影像存 ≥2 年 | **缺失** |
| **工资保证金** | 人社部发〔2021〕65 号 | 合同额 1%–3% 台账 + 差异化减免 + 保函替代 | 部分（保证金域有，减免/替代弱） |
| **质量终身责任制** | 建质〔2014〕124 号 | 五方责任主体 + 授权书/承诺书归档 + 永久标牌档案 | **缺失** |
| **见证取样 / 隐蔽验收 / 旁站** | 国务院令第 279 号第 30/31/38 条 | 见证比例≥30% 校验、隐蔽验收单（带影像签字）、旁站记录 | **缺失** |
| **危大工程 + 双重预防** | 住建部令第 37 号；安委办〔2016〕11 号 | 危大清单 + 专项方案审批 + 专家论证留痕 + 四色风险分级 + 隐患"五落实"闭环 | **缺失** |
| **四流合一（合同/货/资金/发票）** | 国税总局 2014 年第 39 号 | 合同-付款-发票-物资单据关联稽核 | **部分**（发票与合同无外键） |
| **项目级增值税预缴** | 财政部税务总局 2026 年第 14 号 | 按项目分算 + 分包款扣除 + 预缴台账 + 发票备注校验 | **缺**（仅税率字典） |
| **两金压控 / 营业收现率** | 国资委考核 | 应收账龄/周转率、存货周转、现金流与收入匹配 | 部分（有账龄，无周转率/收现率） |

### 2.3 成熟度定位

对照《建筑工程信息化建设评价标准（2025 版）》"起步/应用/集成/协同/智慧"五级：ZW-Insight 已打通"投标—合同—预算—成本—物资—产值—结算—财务"主链路且数据可流转，属**集成级（三级）**；要达**协同级（四级）**需项目-企业两级数据贯通、多参与方协同与辅助决策。对照 T/AIITRE 10004-2023，多数施工企业系统停在"场景级到流程级"，本项目已过线，但**离平台级/生态级仍有系统性差距**。

**两条腿的分工**：国产头部（广联达/新中大/金蝶）强在**成本-业财税-招采-现场**的行业纵深；国际头部（Procore/ACC/Aconex）强在**协同-文档-变更-成本预测**的标准化闭环。

**头部普遍具备、而通用自研系统最常见缺失的 10 个环节**（本项目的缺失高度命中其中 9 个）：

1. **计划与进度的"网络计划内核"**——双代号 CPM、关键线路动态重算、前锋线、多级计划联动、形象进度。（广联达斑马进度 / 品茗智绘 / Buildertrend）
2. **设计/图纸管理与 CDE**——单一文档登记册、版本谱系、Transmittal 传递、图纸会审、不可篡改审计轨迹、BIM 碰撞。（Aconex / ACC Docs）
3. **变更事件的"潜在成本"前置管理**——Procore 的 Change Event → RFQ → 变更单三级链路，把"可能花但未定"的钱先纳入预算 `Pending Cost Changes` 列。
4. **成本预测与 EVM**——Forecast to Complete（四种口径）、EAC/ETC、CPI/SPI、目标成本 vs 实际对比。（Procore / 新中大 / 金蝶）
5. **招采全流程 + 供应商门户**——招标/多轮竞价/密封报价（Blind Bidding）/结构化评标/供应商准入-分级-绩效-门户。（广联达平方网 / Procore Bid Management / 明源云采招）
6. **现场质量安全"清单化+签核"**——标准检查清单模板、不合格项自动生成 Issue、隐患双重预防、危大工程/安全许可前置审批、实测实量。（ACC Forms/Permit / 品茗）
7. **劳务实名制"考勤-工资代发-工效"闭环**——闸机/人脸考勤、银行代发、班组结算、工效测定。（广联达 BIM 劳务 / 金蝶）
8. **资金/税务的保函、票据、融资、税务筹划**。（新中大 / 金蝶 / Sage）
9. **收尾管理**——竣工资料归档、结算审计、决算分析、档案移交、质保期跟踪、项目后评价（lessons learned）。（Aconex closeout / ACC Asset / 新中大）
10. **组合管理 + 开放 API + BI + IoT 接入**。（Procore Portfolio / ACC Data Connector / 广联达 BI+智慧工地）

## 五、缺失环节深度分析（核心）

### 5.1 整段结构性缺失（无表 / 无接口 / 无页面）

| # | 缺失环节 | 证据（只读实测） | 影响 | 对标 |
|---|---|---|---|---|
| M1 | **设计管理（图纸/会审/BIM）** | `图纸会审`=0、`施工组织设计`=0、`BIM`=0（业务代码） | 设计变更无专用载体，图纸散落附件、无版本谱系、变更溯源困难 | Aconex/ACC CDE |
| M2 | **索赔 / 反索赔** | `索赔` java 仅 1 处（风险规则文案）；`反索赔`=0 | 合同履约中的索赔权主张/抗辩零覆盖，签证与索赔混为一谈 | 全部头部产品 |

### 5.3 横向联动断裂（单看每模块都"通"，跨模块对不上）★最关键

这是本项目最系统、也最容易被"逐模块验收"漏掉的一类——**每条链在模块内部自洽，但两条链之间没有单一事实源**：

| # | 断裂 | 现状 | 后果 |
|---|---|---|---|
| X1 | **材料 ↔ 工程量** | `biz_quantity_list`/`biz_boq_item` 与 `biz_material_outbound` 无关联列 | 材料超耗无法按工程量归因；材料成本只能事后归集 |
| X2 | **劳务 ↔ 考勤 ↔ 工资专户** | `LaborPayroll` 金额来自人工汇总工单，无考勤数据源；`WageSpecialAccountService`（财务）与 `LaborPayroll`（劳务）互不触达 | 工资单审批通过不自动触达专户代发；无"考勤工时 × 单价"口径；合规链断裂 |
| X3 | **进度 ↔ WBS** | `BizSchedulePlan.wbsNodeId` 单向引用，WBS 侧无反向进度，二者**无同步机制** | 范围树与进度树各画各的；"某工作包进度到哪/花了多少钱"无法对账 |
| X4 | **变更事件 ↔ 合同累计变更额** | `ChangeEventApprovedEvent` 契约不含 `contractId`，无处理器回写合同累计变更额 | 变更事件批的额度**永不抬高产值上限**（`合同额+累计变更额` 算不准）——26 阶段验收已记录，属**未修**项 |
| X5 | **变更事件 ↔ CBS 潜在成本** | 变更事件只有"批准后调 `current_amount`"；无 Procore 式"潜在成本（Pending Cost Change）"中间态 | 预算/预测失真：未决变更的钱既不在已发生、也不在预测里 |
| X6 | **收票 ↔ 合同开票额** | 收票登记只回写 `biz_other_contract`，对施工/采购合同静默不写；且收票表单**无合同选择器** | 进项发票与合同无法对账，超开票无法拦截 |

## 六、根因分析

**根因一：定位是"记录型台账"，不是"推演型管控"。** 系统能"录、能看、能归集"，但普遍不回答"会怎样"——无 CPM 推演、无 EAC 完工预测、无挣值偏差、无在途额度占用。头部产品的分水岭恰在"预测/推演"（Procore Forecast to Complete、斑马前锋线）。这解释了为什么"成本域事后归集强、事前分析弱"（J）、"进度只有甘特没有关键路径"（M5）。

**根因二：重商务、轻现场与策划。** 资金域（K）与成本域（J）投入最厚，而**设计（B）、索赔（D）、质量安全专项（F）、劳务实名制（I）、收尾（L）这些"现场与策划"环节大量为 0**。定时任务 20 个全在成本/资金/风险侧，现场域仅 2 个，是这一取向的直接投影。这也让系统对"合规审计"的支撑偏弱（§5.4）。

**根因三：单表 CRUD 多，跨环节闭环少。** 146 张 `biz_` 表里，执行域大量是"一张单表 + 增删改查"，而跨模块的"单一事实源"缺位（§5.3 六条断裂）。`feature-ledger` 的分布给出同构证据：**172 条中 42% 停在 L1 单路径 CRUD**，八维缺口里"通知 131/132、追溯 107/132、价值聚合 118/132 缺失"。

## 八、结论

1. **主干扎实、上游与下游两端空心**。系统在"合同→预算→执行→成本→资金→关闭"主干上闭环可跑通（资金域、机械域尤其完整），**缺失集中在"上游策划/设计"与"下游收尾/合规"两端，以及三条横向联动链**。

2. **最强的两处（CBS 成本恒等 + 自动归集对账、滚动资金预测含逾期未付）是行业未见同类公开口径的优势，应固化**；最弱的四处（设计/索赔/实名制/质量安全专项）是**行业头部共识 + 政策强制**双重要求，属结构性欠账。

3. **最危险的模式是"幻影功能"**（§5.5）：前端已画出 CPM/里程碑/关键路径，后端数据模型从未支持。它比"缺按钮"更隐蔽——让使用与验收都误以为能力已具备。同类风险应作为一条检查纪律：**任何前端交互控件，必须有后端数据模型与接口承载**。

4. **若只做三件**：在途额度占用（内控）→ 劳务实名制+考勤（合规）→ 计划 CPM 内核（能力代差）。
