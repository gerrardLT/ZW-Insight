# 全链路 26 阶段验收任务书

> 编制日期：2026-10-12
> 权威来源：`keys/lifecycle-sim-v2.sh`（L4 全生命周期脚本，26 个 `stage_*` 函数即主链的权威拆分）
> 目的：对主链每一个阶段，逐条核验「后端逻辑链路是否通」与「前端操作流程是否通」，找出断裂点

---

## 一、任务目标

对 26 个阶段，每阶段回答两个问题：

1. **后端逻辑链路是否通** —— 数据模型 → 状态机 → API → 调用链 → 跨模块联动 → 校验拦截，哪一环断了
2. **前端操作流程是否通** —— 能否在真实 UI 上从入口走到业务闭环，中间哪一步卡住

**判定口径（三档，必须明确给结论）**

| 判定 | 含义 |
|---|---|
| **通** | 能从 UI 完整走完，且产生正确的数据与状态 |
| **部分通** | 能走通但有缺陷（按钮条件渲染错、字段不回显、某分支走不通、口径不符） |
| **不通** | 存在阻断，无法完成该阶段 |

## 四、每阶段的验收维度

### A. 后端逻辑链路

| 维度 | 要产出什么 |
|---|---|
| 数据模型 | 表名 / 关键字段 / 状态枚举取值 |
| 状态机 | 每个状态由谁推进（方法 + `file:line`）/ 是否有守卫 |
| API | 真实路径 + HTTP 方法 + 参数名（前端 `src/api/*.ts` ↔ 后端 `@RequestMapping` **双向核对**） |
| 调用链 | 谁触发谁（含 Spring 事件 / 监听器 / 定时任务 / Outbox） |
| 跨模块联动 | 回写了哪些**别的模块**的表（这是最容易断的地方） |
| 校验拦截 | 红线判定式与失败语义；负向用例能否真被拦截 |
| **判定** | 通 / 部分通 / 不通 + 证据 |

### B. 前端操作流程

| 维度 | 要产出什么 |
|---|---|
| 入口 | 菜单路径 + 路由 |
| 操作步骤 | 从进入页面到业务闭环的**实际点击序列** |
| 接口调用 | 实际发出的请求（`waitForResponse` 抓包或真机实测） |
| 状态回显 | 操作后列表/详情是否正确反映（易漏：字段名错、不刷新、条件渲染错） |
| 边界 | 按钮条件渲染 / 必填校验 / 空态 / 错误提示 |
| **判定** | 通 / 部分通 / 不通 + 证据 |

### C. 判定证据要求

- **静态证据**：`文件:行号`
- **动态证据**：真机接口响应摘要（URL + code + 关键字段）或 UI 抓包结果
- **禁止**：只凭读代码就断言「通」——UI 流程必须实测（本项目历史上多次出现「代码看着对、真机走不通」）

## 六、纪律约束（强制）

1. **严禁本地启动 JVM/mvn**（含 `mvn test`/`verify`/`test-compile`）——用户 2026-10-07 硬性指令，后端编译与测试只走 CI
2. **只操作 tenant 1 演示租户**；写用例统一 `E2E_TEST_` 前缀并在收尾清理；不动种子（90001-90004 等固定 ID 段）
3. **禁止静默跳过 / 禁止标记为通过 / 禁止 mock 降级**；走不通就如实记录原因与卡点
4. **行尾必须按各文件自身 HEAD 归一**——同目录 CRLF/LF 混存，`grep -c $'\r'` 会撒谎，只能用 Node 逐字节量
5. **中文在 Git Bash 下会 mojibake**——脚本输出用 ASCII 标签，中文只写进文件
6. 改动前端后必须跑 `npm run test` + `npm run build`；改后端只能靠 CI 编译验证
7. 数据库写操作前先只读探查 + 备份；DDL 在 MySQL 会**隐式提交**，事务回滚保护不了
8. 迁移脚本必须**双轨放置**（`db/migration/` + `deploy/db-init/`）且幂等
