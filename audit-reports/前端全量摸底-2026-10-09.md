## 三、实锤缺陷清单（静态确认，按严重度）

### P1-A 雪花 ID 被 Number() 显式转换（精度截断，提交/查询错 ID）
| # | 位置 | 影响 |
|---|---|---|
| 1 | views/finance/payment-apply.vue:641-642 | 采购/劳务结算跳转付款申请时 `Number(projectId/contractId)`，19 位 ID 丢精度 → 预填合同错位或后续查询失败 |
| 2 | views/finance/receivable/index.vue:343 | 应收下钻 `Number(row.id)` → 下钻链查错/查空 |
| 3 | views/site/inspection/detail.vue:186 | 整改提交 `Number(route.params.id)` → 提交到错误检查单 |
| 4 | components/DrillDownBreadcrumb.vue:427 | 下钻跳转 `Number(row.projectId)` → 跳错项目 |

（cockpit/fund-center、fund-plan、fund-dashboard 中的 `Number(row.overdueUnpaid)` 是金额判断，非 ID，不属本类。）

### P1-B 公共 Selector 类型谎言 + 严格等值比较（选中回调静默失败隐患）
后端 Jackson 将雪花 ID 序列化为字符串；以下 8 个公共选择器 `modelValue?: number` 与真实不符，且 `handleChange` 用 `o.id === val`：
ContractSelector / MachineSelector / PostSelector / SubcontractSelector / SupplierSelector / TeamSelector / OtherContractSelector / PurchaseContractSelector（ProjectSelector 已在早前修复为 number|string）。
当前多数链路恰好 string===string 成立；一旦父组件用 number 回填（编辑回显、路由预填），查找静默返回 undefined → 名称不回填、提交缺字段。属定时炸弹型隐患。

页面级同类严格比较（5 处）：budget/change/form.vue:248 · contract/form.vue:193 · labor/work-order.vue:158 · labor/payroll.vue:182 · material/stock.vue:189。

### P2-A 级联选择器无竞态守卫（旧响应覆盖新结果）
finance/monthly-analysis · labor/output · labor/reward-punish · labor/settlement · labor/work-order · purchase/settlement（合同/班组级联查询无请求序号；快速切换时晚到响应覆盖当前选项列表）。

### P2-B 加载失败静默
- workflow/designer/PropertiesPanel.vue:148-175：角色/用户加载失败静默吞掉，下拉空且无提示无重试；且 `NODE_ENV==='test'` 直接跳过加载（测试环境钉死，现测无法证明该链路）。
- 全库 `catch {}` 空 catch 共 97 处：多数可能是合法的取消/忽略，需分模块逐个判定，未逐一确认。
