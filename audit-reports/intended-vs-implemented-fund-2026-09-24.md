## 二、P0 实质差距（会导致错误经营决策）

### P0-1 资金状态只有 2 档，缺「部分付款」

- **意图**：资金流转 §8 明确列出 **11 档**状态（`01已申请 / 02审批中 / 03已批准 / 04已发生 / 05已确认应付 / 06待付款 / **07部分付款** / 08已付款 / 09待结算 / 10已结算 / 11已关闭`），并强调"每笔资金不要只有'付了/没付'……这样才能真正看到资金未来压力"
- **实现**：`BizPaymentApply.java:21-24` 仅 `PAY_STATUS_UNPAID` / `PAY_STATUS_PAID` 两档；`PaymentApplyService.refreshPayStatus` 逻辑为"累计勾稽 ≥ 付款金额才置 PAID"
- **矛盾点**：银行流水侧**已支持部分勾稽**（V2026_56 的 `match_amount`、`bank-flow/index.vue:170` 提示"支持部分勾稽"），但付款申请状态无法表达"部分已付"
- **影响**：一笔 100 万付款申请已实付 60 万，系统显示"未支付"、`expected_payments` 仍按 100 万计入预测 → **重复计算 40 万资金压力**；老板看到的待付金额虚高
- **修复**：新增 `PARTIAL_PAID` 档（`0 < 累计勾稽 < 付款金额`），预测付款侧按**剩余未付额**（`payment_amount − 已勾稽合计`）计入而非全额

### P0-2 资金缺口公式与文档不同（未减可用资金）

见第一节 #1、#2。修复需同时改：
- `computeGap90Days()`：`缺口 = Σ未来预计支付 − min(可用资金, Σ预计支付)`，或按文档原式 `未来预计支付 − 可用资金`
- `FundGapRiskRule`：引入"可覆盖"判定（`账户可用资金 ≥ 缺口` → 🟡；否则 🔴；无缺口 → 不产生）

### P0-3 「应付未付」口径缺失

见第一节 #3。资金流转 §3.1 要求资金控制账同时有"应付金额（已产生付款义务）"与"已支付金额"，§12 项目经营总览也要求"已确认应付 / 已付款 / **应付未付**"三行并列。
- **可用数据源**：各支出合同的 `cumulative_settlement`（累计结算 = 已确认应付）与 `cumulative_paid`（已付）——**这两列已由 R7 审计基线校验勾稽一致**（`audit-data.ps1` Section 3 全 0 MISMATCH）
- **修复**：`应付未付 = Σ(cumulative_settlement − cumulative_paid)`，与"已批未付"并列展示（两者语义不同，不可互相替代）

### P0-4 §12「项目经营总览」12 指标缺 2 项关键现金指标

- **意图**：资金流转 §12（"项目管理层最终只看一张表"）12 项含 **本月现金需求**、**三个月资金需求**
- **实现**：`CockpitService.getOverview():80-93` 返回 10 个字段，无这两项；单项目详情页（`project-cost-control.vue`）亦无
- **影响**：这是文档定义的"老板唯一必看表"的核心两项，缺失后无法回答"这个月要准备多少钱"
