## 3. 本轮处理的重点问题与安全防护

1. **合同竣工结算审批（第四项决议）**：
   - BPMN `final_settlement_approval.bpmn20.xml` 任务节点由 `assignee="${initiator}"` 改为 `flowable:candidateGroups="PROJECT_MANAGER"`。
   - `ApprovalService.SELF_APPROVAL_GUARDED_TYPES` 补充 `FINAL_SETTLEMENT`，发起人不能审批自己的单据。
   - 双机租户 1 与 9999 重新部署生效。
2. **徽颖生产库 3 条孤儿记录治理**：
   - 探针发现 `V2026_84` 迁移在空种子库中给未初始化的角色 90061 插入了 3 条菜单关联，导致 Section 5.1 报 FAIL。
   - 在徽颖服务器进行了 mysqldump 备份并落盘到 `/root/zwi-deploy/backups/sys_role_menu_orphan_fix_backup.sql`。
   - 执行清理并复查孤儿数为 0，R7 审计 FAIL 归零。
   - 新环境编排脚本 `deploy/db-init/86_V2026_84__labor_deep_opt.sql` 已补充 `EXISTS (SELECT 1 FROM sys_role WHERE id = 90061)` 守卫，杜绝新空库再次踩坑。
3. **退回重审回调状态兼容（L4 阶段 9E）**：
   - 把付款申请、产值上报、竣工结算的审批回调收紧为“仅 SUBMITTED”时，由于“退回发起人”只将单据置为 REJECTED/DRAFT 而不终止流程，导致重审通过时回调报状态异常。
   - 三处回调均已扩展为兼容被退回状态，并补全单元测试覆盖。
4. **单测实体列缓存补全**：
   - 补全了 6 个测试类对 `LambdaUpdateWrapper.set()` 的 `TableInfoHelper.initTableInfo` 预初始化，防止无 Spring 容器测试报错。
5. **安全与并发防御**：
   - 消息标记已读零命中抛异常；
   - 催办 WebSocket 采用 Jackson 序列化防注入；
   - 变更事件必须更新行数命中才写 Outbox；
   - 产值与分包结算均下沉为原子 SQL 上限检查与状态 CAS。
