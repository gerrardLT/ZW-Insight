# 双机业务与审批权限审计修复

## 授权与范围
2026-10-09 用户授权可逆修复、实际测试、独立只读审阅后提交与双机部署。审计报告仅为线索，逐项重查源码与真实主机。保留用户未跟踪报告及其他会话改动。

## Requirements
1. 角色及权限查询过滤用户/角色/菜单启用、逻辑删除与租户；按真实架构保留内置全局共享角色，不以用户名授权。
2. 普通任务详情与业务详情统一先验证租户及相关人；SUPER_ADMIN 不得跨租户。允许同租户办理人、候选人/有效候选角色、发起人、已办参与人；拒绝无关人。
3. 审批必须取得真实源单，不得将缺失、权限失败或 SQL 错误当成功。检查字段脱敏与前端竞态、claim 后意见保留。
4. 双机分别核对 IP、容器、数据库、企业；重查跨租户关联、项目引用、积压、自审指派、FINANCE 组及已删入职实例。无法唯一推断业务目标的记录保留，列入用户决策。
5. 仅徽颍 tenant1 最新33流程指定真实 wangting/wangshuangtao 用户 ID；保留节点、分支、监听器及金额变量；不改主环境为不存在用户，不自动迁移现有实例。
6. R7 SQL 失败不能计零违规；完整新旧基线按真实结果比较。

## 安全与验收
生产写前逐行只读证据、目标表备份并验证、幂等守卫；Flowable 经应用 API/引擎，不直接写 ACT。禁止按积压认垃圾、全库清理、占位业务、新用户或扩大权限。写入测试只用 tenant9999；不得猜密码、伪造 JWT 或输出凭证。后端测试仅 CI/安全非生产服务器，禁止本地 Java/mvn。普通角色凭证缺失如实注明 HTTP 边界。

提交前由用户主会话调独立 Agent 只读审阅全部 scope，无 P0/P1 后方可提交部署。frontend dist 在 CI runner 构建；禁生产构建与 fast_deploy 绕过失败。最终 audit-reports 持久验收记录 SHA、run、备份回滚、改前后计数及未修项。
