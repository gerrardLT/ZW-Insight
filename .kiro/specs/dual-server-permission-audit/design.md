# Design

## 最小实现
沿用 SysUserMapper 现有查询签名，在 SQL 中 JOIN 用户和角色，绑定实际用户租户；共享角色策略先核实 schema/种子及线上记录再落地。复用既有任务相关人判定，将其收敛到 ApprovalService，避免 BusinessDetailService 反向注入形成循环；所有详情授权在聚合变量前完成。已有操作权限与防自审守卫不降级。

源单读取沿用白名单、绑定参数、tenant/deleted 过滤和敏感字段脱敏；办理入口验证真实源单可用。前端沿现有审批状态实现防竞态及错误显式阻断，不新增依赖。

## 线上策略与风险
两机分别建立只读明细及节点级流程清单。只有唯一证据支持的项目引用可修；其余保持记录，不改金额累计。跨租户角色关联精确守卫修复。流程定义只针对43 tenant1部署新版本，结构差异须仅审批候选配置；既有实例保持原状。已删入职实例与FINANCE旧候选组若应用 API 缺少安全处理能力则登记未决，不直接 SQL 修改引擎。

## 测试
扩展现有 Mockito 单测覆盖正常与拒绝：跨租户超管、无关人、候选人/角色、发起人、历史参与人、删除停用角色/菜单、源单缺失及 SQL 错误。前端测试覆盖加载竞态、claim意见保留和详情失败禁办理。运行正确 root 的 consistency-audit。后端 CI verify，不能以源码检查代替执行；受阻登记 test-maturity-upgrade 台账。

## 回滚
代码以本 scope commit revert 回滚，不回退他人修改。生产 SQL 保存精确目标备份、SHA256、行数和恢复守卫；仅恢复本次改动的关联/引用，不覆盖其后业务。BPMN 保存原XML及节点对比，需要回滚时经应用部署原配置为新版本，历史版本/实例不硬删。部署使用既有 runner 产物与原版本镜像，确认无重复 node/vite。验收报告保存每项实际回滚证据。
