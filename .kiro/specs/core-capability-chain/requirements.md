# 核心能力链补全需求

来源：`docs/deep-opt/真正需要补充的核心能力清单-2026-10-16.md`（竞品二次对比 + 读码 + 三路复核 + 行业规范校准）。
2026-10-16 用户批准实施，并确认两项产品决策：

1. **签证为合同累计变更额唯一财务生效源**：变更事件只做事实评估与 CBS 传导；签证可选关联事件，有关联时事件侧不回写合同累计。
2. **薪资发放先只读呈现**：不接入 CBS 归集，不动 `CostRollUp`，是否入账待会计政策明确后另立项。

## 需求清单

### F 正确性修复（不新增业务功能）

- F1 预算控制闭环：受控合同提交审批时按最新金额重新校验预算（补齐劳务 submit 缺口）；预算 WARN 经 `UrgeNotifyEvent` 真实通知项目经理，无收件人记失败，不伪造成功。
- F2 签证↔变更事件单一生效源：签证可关联变更事件（同合同同项目、一个事件至多一张有效签证，DB 唯一 guard）；变更事件审批时若已有有效关联签证则不回写合同累计变更额；签证审批无论有无关联均回写。
- F3 税差指标正名：`taxDifference`（实为发票金额差）更名 `invoiceAmountDifference`，语义如实标注；真实税额指标待销项发票台账（C3）落地后基于票据事实计算。

### C 核心业务能力

- C1 收入侧过程结算：`biz_final_settlement` 扩展 PROCESS/FINAL 两型；来源单据（已批产值/签证/手工行）带申报、审定、争议、扣款（预付款扣回/质保金扣留/其他）与核减原因；审批通过原子回写合同 `cumulative_settlement` 并生成应收；驳回/撤回/终止/删除释放来源占用并反冲；FINAL 汇总既有 PROCESS、保留置 SETTLED 行为。开票额度口径不变（累计产值−已开票）。
- C2 合同收付款条款结构化：通用条款表（PREPAY/PROGRESS/FINAL/RETENTION，触发条件、计划日期、比例/金额、扣回规则、宽限期）挂接各类合同；合同修订时条款入前后快照；PROCESS 结算审批按 RETENTION 条款幂等计提质保金（补 `biz_retention_money.contract_id`）、按 PREPAY 条款给出建议扣回额。
- C3 税务事实链：四类支出合同补税率/不含税/税额（服务端派生，历史留 NULL）；销项发票台账（数电号码、蓝/红字与原票、查验与入账状态、租户内有效身份唯一）；进项发票补查验/用途/入账状态；合同 `cumulative_invoice_amount` 语义不变，界面双口径并列；驾驶舱补销项税合计/进项税合计/估算税额差（basis 注明）。
- C4 材料结算价差：结算明细保留来源单价/结算单价/价差/原因；租户级容差（比例+绝对值，默认 0）；超容差强制原因；保存/提交/审批三处服务端重算；LEGACY 整单模式不引入价差。
- C5 成本只读指标与口径治理：「工资及点工累计审批发放」与「劳务累计结算」并列只读呈现并明示未入 CBS；新增回款率四种（/合同额、/产值、/开票额、/累计结算）与产值毛利/结算毛利（CBS 不可用时明示），统一携带分子/分母/basis 元数据。

## 强制边界

不合并五张支出合同表；不建合同执行单；不持久化在途 `payingAmount`；不做多维大宽表；不动 CBS Rollup 与 `total_expense` 审批口径；不本地跑 Java/mvn、不推送、不部署；迁移双轨幂等（V2026_107 起）；新 Mapper 必须带 `@Mapper`；历史缺失不猜填；测试租户 9999；R7 不变量（`cumulative_*` 仅由 APPROVED 单据汇总、CBS 流水恒等）不得破坏。
