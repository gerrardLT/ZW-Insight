## Design Specificity Verdict

**判定：FIELD-SPECIFIC（为工地现场定制，非通用 H5 模板）**

1. **领域语言贯穿全部 45 个页面**：劳务点工/机械台班/变更事件/材料入库；tabBar（首页/工作台/审批/我的）对应现场工作流层级，非通用 SaaS 模式。
2. **户外高对比模式是现场加固需求而非主题皮肤**：`tokens.css` 中 `:root[data-theme="outdoor"]` 独立配置纯黑白对比 >14:1、加硬边框、品牌橙按日光可见度重调。
3. **手套友好触控目标进入令牌层**：`--zw-touch-target-min: 44px` 显式定义（tokens.css:75）。
4. **离线优先是一等公民架构**：`OfflineBanner` + `offlineSubmit.ts` + `syncEngine.ts` + `offlineCache.ts` 构成完整离线 UX 层；每个录入页（材料入库、劳务点工、机械台班、财务付款、安全检查）均走 `submitOrQueue()`。
5. **水印相机是测绘仪器语言**：GPS + 时间戳 + 编号以 canvas 嵌入（非 PNG 叠加），瞄准标尺十字线配橙色强调，贴近工程测量工具而非消费级相机。
6. **Hazard 条纹语义化使用**：仅出现在有功能含义处（离线横幅、登录侧栏、水印照片叠加），非装饰。

**确定性扫描（detect.mjs，exit code 2，DEGRADED 模式）**：1 条发现。
- `styles/signature.css:125` side-tab（`.plate-header::before` 3px 左侧竖标条纹）— **判定误报**：属项目级"工程铭牌签名"视觉契约，与 PC 端 `global.scss:158`、`element-override.scss:472` 同源，非 AI slop。
- **扫描器可靠性告警**：detect.mjs 因缺少 HTML parser 依赖（htmlparser2/css-select/css-tree/domutils）降级为 regex-only，自报"findings are an undercount, not a clean bill of health"。自定义属性、选择器匹配与计算对比度**未被评估**，故移动端确定性结论只能视为下限，不能作为清白证明。本轮已用 grep 补充事实数据弥补。

## Overall Impression

真正为工地写出来的产品：离线优先架构不是降级兜底而是主路径，户外高对比模式说明团队理解真实现场条件，品牌签名（橙 + hazard 条纹 + 直角纪律）跨全部组件一致。三个真问题：① 长表单单屏堆叠 8-12 字段违反 Miller 定律；② 离线状态对用户完全不透明（队列数/冲突/同步中均不可见）；③ 帮助与引导零存在，新人只能靠 placeholder 猜。最大机会：把"能离线录入"升级为"离线也心里有数"，并把多字段表单改为一次一个决策的渐进式流程。

## What's Working

1. **离线优先 UX 模式（4/4）**：每笔写操作经 `submitOrQueue()`，在线即 commit、离线即入 `STORAGE_KEYS.OP_QUEUE` 标 PENDING；横幅仅在 `network.isOffline=true` 出现；Toast"已存入离线队列，联网后自动同步"给即时安心且不虚假承诺；同步引擎 3 次重试 + 5 分钟间隔（lines 314-332）+ 版本冲突检测（HTTP 409/bizCode 409）。这是队列优先持久化 + 服务端优先语义，不是"缓存后同步"。
2. **工业精密视觉语言（3.5/4）**：三条硬规则跨双端执行——橙底配深色字（#ff6b00 + on-primary #14161a，tokens.css:34 注释明确禁用白字压橙以保对比度）、2px 角标（伪元素左上/右下直角括号，无曲线）、单层阴影（`--zw-shadow-card: none`，仅浮层用 `--zw-shadow-overlay`）。
3. **批量审批界面（4/4）**：`approval/index.vue` 复选框选择 + 全选开关 + 未选中禁用态（lines 47-53）+ 实时计数 `批量同意(${selectedIds.length})`；离线时 `rejectIfOffline` 阻止入队并明确报"审批操作需联网进行，请联网后重试"。这是不牺牲新手清晰度的高手效率标杆。

## Priority Issues

- **[P0] 拇指区布局策略缺失 + 触控目标不达标**
  - Why it matters: 主操作按钮位于可滚动表单底部（padding-bottom:120rpx），大屏机（iPhone 14 Pro Max 926px）单手拇指够不到；戴手套现场人员会放弃或误触邻近元素。复选框仅 36rpx×36rpx，部分按钮 80rpx≈40pt、72rpx≈36pt，低于 44×44pt 最小标准。
  - Fix: ① 主操作改 sticky footer `position: fixed; bottom: env(safe-area-inset-bottom)`；② 全部交互元素高度 ≥88rpx（375pt 设备 = 44pt）；③ safe-area-padding 统一覆盖（OfflineBanner 已有，提交按钮缺失）。
  - Suggested command: `/impeccable adapt`

- **[P1] 表单分块过载**
  - Why it matters: 材料入库表单 12 字段（项目 picker + 模式选择 + 合同 picker + 材料明细卡 + 数量输入）；安全检查 8 字段含条件区块。全部单屏纵向滚动，超出 Miller 7±2。现场人员中途被打断后回来，无会话持久化（仅 Pinia localStorage，杀进程后是否保留不明）。
  - Fix: ① 拆向导流：Step1 项目与合同 → Step2 材料明细 → Step3 复核提交；② 渐进披露：整改字段仅在 result="不合格" 时出现，高级选项收进"更多"；③ 会话恢复：onHide 存 sessionStorage，onShow 还原。
  - Suggested command: `/impeccable onboard`

- **[P1] 离线状态透明度缺口**
  - Why it matters: 横幅文案只说"联网后将自动同步"，但用户看不到：队列了几笔？有无冲突？是否正在同步？`network` store 已暴露 `queueCount` 与 `isSyncing`，UI 层从未读取展示。地下室录 10 条安全检查后回到地面，无法确认是否真同步，用户以为成功而后端零记录 → 信任崩塌。
  - Fix: ① tabBar 工作台图标角标显示 queueCount（>0 时，如 📮3）；② "我的"页增同步状态模态：上次同步时间、待同步数、失败冲突；③ 冲突标记落库带原因字段，在审批/列表视图暴露"解决"CTA。
  - Suggested command: `/impeccable clarify`

- **[P2] placeholder 作为唯一指引**
  - Why it matters: 输入字段大量仅靠 placeholder 说明（122 处 placeholder vs 166 处 form-label/label）；uni-app 聚焦后 placeholder 消失，用户对期望格式（日期 YYYY-MM-DD？数量整数还是小数？）零记忆辅助。placeholder 色 `--zw-text-quaternary: #a3a8b0` 对白底对比 3.2:1，违反 WCAG AA 4.5:1；读屏也不可靠播报 placeholder。
  - Fix: ① 用常驻 `form-label` 置于输入框上方替代 placeholder 承载语义；② 边界场景加辅助文案"格式：YYYY-MM-DD（如 2026-09-11）"；③ 作提示时把 quaternary 提升到 secondary（#4a4f57）。
  - Suggested command: `/impeccable harden`

- **[P2] prefers-reduced-motion 零声明（动效无障碍缺口）**
  - Why it matters: 移动端 grep 结果为 0 处，PC 端有 1 处全局降级。前庭功能障碍用户在移动端仍会承受全部动效（含 active-press 缩放、进度条过渡、水印相机扫描动效），且无法关闭。
  - Fix: 在 `tokens.css` 或 `signature.css` 增全局 `@media (prefers-reduced-motion: reduce)`，把 animation/transition 降到最小，但保留状态变化的非动效表达（颜色/文字），不要一刀切 0.01ms 抹掉有用反馈。
  - Suggested command: `/impeccable harden`

- **[P3] 空状态单一化无诊断价值**
  - Why it matters: 全部空状态同一模式 `<view class="empty"><text>暂无项目</text></view>`（居中 quaternary 文字，40rpx padding），无法区分"未分配项目"vs"网络取数失败"vs"离线缓存过期"vs"无权限"。压力测试者无法判断空态反映数据现实还是权限失败。
  - Fit: 建 `EmptyState` 微组件带 type 变体（data/error/offline/permission），error 变体加图标 + 重试，permission 变体加联系管理员 CTA；配"发起第一个施工日志"深链快速启动。
  - Suggested command: `/impeccable delight`

## Persona Red Flags

**Casey (Distracted Mobile User) — 6 项红旗**：
1. 中途离开无状态保留：所有 create 表单均无 onHide 写 sessionStorage，返回即清空
2. 弱网性能未优化：45 页应用包需重解析（Pinia stores、syncEngine、watermarkCompositor），pages.json 未检出路由分包懒加载策略
3. 触控目标不一致：提交按钮 88rpx（设备相关，可能 <44pt），审批复选框仅 36rpx×36rpx（approval/index.vue:228）
4. 无拇指区优化：主操作在滚动末端，无 sticky footer；6.7 寸设备底部行需双手
5. 表单要求过多打字：材料编码需手输，条码扫描 `handleScan` 在 H5 平台被 `#ifndef H5` 隐藏
6. 离线同步不透明：无法验证排队操作是否完成，无成功回执

**Jordan (First-Timer) — 4 项红旗**：
1. 工作台网格 emoji 图标（📑🚜👷📷📝📦🔍）下方无文字，依赖文化识字；新工人不会把"机械台班"对应到铲子图标
2. 术语无词典：合同采购量 vs 本次实收数等无内嵌定义、无 tooltip
3. 无引导教程：启动直达仪表盘，无 tab 说明/离线优势/首个任务起步引导
4. 成功信号模糊：Toast 泛化"提交成功"，不确认是哪条记录、不给详情验证链接

**Sam (Accessibility) — 3 项红旗**：
1. 仅颜色编码状态：成功/危险/警告纯靠绿红橙徽章（ZwStatusBadge.vue:18），无形状/纹理辅助，色盲用户无法区分
2. 无焦点指示：scoped 样式中无 `:focus-visible` 规则，键盘/读屏导航缺可见焦点环
3. 图片替代文本缺失：相机预览与缩略图均无 alt；uni-app image 组件对 aria-label 支持有限，仍需自定义 slot 兜底

**Riley (Stress Tester) — 5 项红旗**：
1. emoji 边界未处理：安全检查描述 textarea maxlength=500 接受 emoji，后端 VARCHAR/TEXT 对 Unicode 代理对可能存储错误或截断
2. 极端数据量未压测：分页 page/size 15，积压到 500 条时 scroll-view 增量加载（page++）但取数期间无 spinner，仅"加载中..."文字
3. 长文本截断无出口：项目名超 30 字符用 line-clamp-2 省略，点击无预览模态，全文不可达
4. 杀进程重进无提示：离线队列在 storage 中持久，但首页无待处理操作的可视指示
5. 客户端时间戳可篡改：`Date.now()` 非 NTP 同步，设备时钟前后拨数小时会打乱同步引擎按时间戳升序的提交顺序（syncEngine line 155）

## Minor Observations

1. 字体栈用系统栈（-apple-system/PingFang SC/Microsoft YaHei）利于性能，但 Android 缺 Barlow Condensed fallback，display 族应补 `'Roboto Condensed'`。
2. `font-variant-numeric: tabular-nums` 在所有金额字段一致应用 ✅（19 处硬编码色远低于 PC 端 446 处，令牌纪律更好）。
3. `.active-press` 工具类在 tokens.css:98-102 定义（opacity + scale 变换），但跨组件应用不一致。
4. 暗色令牌镜像 PC dark.css（`:root` + `page` 双选择器），但原生 tabBar 背景覆盖只设了 `uni-tabbar .uni-tabbar`，未覆盖 `uni-tabbar-item` 激活态样式。
5. 水印 canvas 硬编码 600×800px（ZwWatermarkCamera line 107-110），原图宽高比差异大时部分照片被拉伸或裁切。
6. 网络类型粒度仅 wifi/4g/none，5G/NB-IoT 映射为 unknown；对 UX 决策够用，但排障可见性受损。
7. 安全区适配仅 5 处声明（`safe-area-inset-bottom`/`--zw-safe-bottom`），需核对是否覆盖全部底部固定元素。
8. `will-change` 2 处；`outline: none` 0 处 ✅。

## Questions to Consider

- 是否需要"离线优先模式"开关？当前被动检测，高手可能想故意延迟同步到批量上传窗口（如收工 Wi-Fi 集中上传 vs 持续流式）。
- Hazard 条纹的语义是否该超出"离线"？同一斜纹可用于逾期任务、被驳回合同、安全关键警告，形成跨界面紧急度视觉速记。
- emoji 图标导航真的包容吗？工地人员年龄跨 18-60 岁、数字素养差异大，是否提供"经典模式"（全部图标下加文字）可选，或彻底承诺文字优先路径？
- 是否需要二维码"配对"流程？设备扫码注册 → 绑定 UUID → 后续日志预填机械选择器。当前流程是 picker 弹窗滚动 50 台设备再点选，规模化隐忧已现。
- 照片水印是否需要地理围栏校验？GPS 技术有效但可被虚拟定位 App 伪造，是否要硬件级认证（Android SafetyNet / Apple DeviceCheck），还是在 P0 范围接受该风险？
