## 一、定位与边界

### 1.1 本规划覆盖什么

浏览器测试在本项目对应测试金字塔的 **L5 层**，打真实服务器（默认 `http://129.204.3.200:18081`，后端 `:18080`），登录态由 `e2e/fixtures/auth-real.setup.ts` 真实登录后落 `e2e/.auth/storage-state.json`。

现有 4 个 Playwright project，本规划**只针对 `e2e-real`（UI 功能与链路）**：

| project | 职责 | 本规划是否涉及 |
|---|---|---|
| `setup-real` | 真实登录，产出 storageState | 作为前置依赖 |
| **`e2e-real`** | **UI 功能 + 核心链路**（`e2e/tests/real`） | ✅ **规划对象** |
| `consistency-real` | 前端展示 vs 后端响应字段级比对（`e2e/consistency`） | ❌ 分工：字段格式/枚举翻译归它 |
| `visual-real` | 关键页截图基线比对（`e2e/visual`） | ❌ 分工：布局回归归它 |
| `docs-shots` | 帮助文档配图 | ❌ 非回归套件 |

### 1.2 边界与不变量

- **真实接口真实流程**：禁止 mock、禁止静默 fallback、禁止 `log` 后假装通过（AGENTS.md §1、§8）
- **只操作 tenant 1 演示租户**；写用例统一加前缀（建议 `E2E-<suite>-<ts>`），用例收尾清理自建数据，不动演示种子（90001-90004、99101 等固定 ID 段）
- **可重复执行**：每条链路必须能连续跑两次不互相污染（唯一键 guard / 幂等清理）
- **断言不满足一律 FAIL**，不跳过（AGENTS.md §8「测试受阻汇报规则」）

### 1.3 明确不在本规划内

- 移动端 `zw-insight-app`、供应商门户 `zw-supplier-portal`：两者目前**无 e2e 基建**（无 playwright.config、无 `e2e/` 目录），需另立套件后再规划
- L4 全生命周期（`keys/lifecycle-sim-v2.sh`）：走 API 不走 UI，与本规划正交

## 二、测试模块分类

### 2.1 两条正交分类轴

**轴一 · 业务域**（决定测试数据与登录账号，沿用现有分组）

| 域 | 模块 | 数据特征 |
|---|---|---|
| **A 核心主链** | project / tender / contract / budget | 演示种子齐全（90001-90004），链路最长 |
| **B 支出域** | material / machine / labor / subcontract / purchase | 单据密集，勾稽关系强 |
| **C 财务·现场·人事域** | finance / site / hr / archive | 金额口径与审批后生效，是缺陷高发区 |
| **D 平台支撑域** | system / basedata / message / workflow / platform / user | 配置类为主，权限耦合 |

**轴二 · 套件类型**（决定 spec 组织方式与执行策略 —— 本规划新增）

| 类型 | 代号 | 特征 | 执行策略 |
|---|---|---|---|
| **全链路串联** | `CHAIN` | 跨 5+ 模块的一条业务生命周期 | 单 spec 串行，`workers=1`，一次跑通一条链 |
| **模块闭环** | `MODULE` | 单模块 列表→新增→提交→审批→回写 | 按模块独立 spec，模块内串行 |
| **平台支撑** | `PLATFORM` | 登录/权限/配置/消息/工作流 | 多为只读或配置，可并行 |
| **只读展示** | `READONLY` | 看板/台账/档案，只断言渲染与字段 | 可并行，最安全，适合做冒烟 |

## 三、「核心链路」的判定标准

一条链路要入选，必须满足：**由「产生/推进业务数据」的动作序列组成，且终点存在可硬断言的状态或金额回写**。

据此排除三类：纯配置增删改查（无状态推进）、纯只读列表渲染（无写动作）、字段格式比对（归 consistency 套件）。

每条链路的用例统一按四段式描述：**前置 → 步骤（→串联）→ 断言（硬断言）→ 依赖数据**。

### 6.2 数据纪律

- 写用例统一前缀 `E2E-<suite>-<timestamp>`，**收尾删除自建数据**（含下游子表）
- 删除单据必须**同步回滚累计值**（否则制造反向 MISMATCH）
- 优先复用持久化演示种子做只读断言（90001-90004 等固定 ID 段）
- 不触碰 `sys_user` / `serial_number_rule` 等系统表

### 6.3 执行策略

| 套件类型 | workers | 理由 |
|---|---|---|
| CHAIN | 1 | 长链跨模块，写操作互相依赖 |
| MODULE | 1（写）/ 4（只读） | 避免并发写库冲突 |
| PLATFORM | 2 | 多为只读或配置 |
| READONLY | 4 | 最安全 |

### 6.4 已知阻断项（需先决策，不得静默跳过）

| 阻断项 | 影响 | 处置建议 |
|---|---|---|
| 登录页滑块为宝塔 WAF 的 TAC，自动化过不去 | 所有 UI 用例 | 走应用登录接口取 JWT 后注入 localStorage（现有 `auth-real.setup.ts` 已实现） |
| `/system/monitor` 为占位页 | D3-S8 | 现状钉住，标记为「未实现」 |
| 项目提交不产生 Flowable 待办 | CHAIN-1 的审批段 | 属既有设计（直批），用例按实证断言 |
| 产值上报合同下拉为空 | CHAIN-1 产值段 | 已定位根因（ProjectSelector 未开 default-first + 硬编码 EFFECTIVE），修复前该段登记受阻 |
